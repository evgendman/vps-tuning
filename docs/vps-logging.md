# Ограничение размера системного журнала (systemd-journald)

**Статус:** ограничения настроены на назначенном новом VPS. На втором VPS и на домашнем сервере эта политика данным изменением не вводилась.

## 1. Зачем ограничивать журнал

Systemd journal хранит системные и сервисные события, полезные для диагностики. Без заданных лимитов объём журналов может постепенно увеличиваться и занимать заметную часть диска VPS.

Настройки ниже ограничивают объём хранения и резервируют свободное место. Они не отключают журналирование и не меняют правила чтения SSH-событий Fail2ban: jail использует backend `systemd` и продолжает читать события из journal.

## 2. Применённые параметры

Локальный drop-in:

`/etc/systemd/journald.conf.d/60-limits.conf`

Содержимое:

~~~ini
[Journal]
SystemMaxUse=256M
SystemKeepFree=1G
SystemMaxFileSize=16M
SystemMaxFiles=20
~~~

| Параметр | Значение | Назначение |
|---|---:|---|
| `SystemMaxUse` | `256M` | Ограничение суммарного места, используемого постоянным журналом |
| `SystemKeepFree` | `1G` | Требование сохранять не менее 1 ГБ свободного места на файловой системе |
| `SystemMaxFileSize` | `16M` | Ограничение размера отдельного journal-файла |
| `SystemMaxFiles` | `20` | Ограничение количества journal-файлов |

Фактический предел хранения зависит также от свободного места на файловой системе: journald учитывает оба ограничения. Эти значения не означают, что журнал всегда занимает ровно 256 МБ.

## 3. Как применили настройки

1. Проверили исходную конфигурацию journald и фактический размер журнала.
2. Создали отдельный drop-in в `/etc/systemd/journald.conf.d/`, не изменяя основной файл `/etc/systemd/journald.conf`.
3. Поместили в него параметры из раздела 2.
4. Перезапустили только `systemd-journald`, чтобы применить конфигурацию.
5. Проверили состояние службы, эффективную конфигурацию и использование диска.

Пример команд для воспроизведения на целевом VPS (после подтверждения, что это именно тот сервер):

~~~bash
sudo install -d -m 0755 /etc/systemd/journald.conf.d

sudo tee /etc/systemd/journald.conf.d/60-limits.conf >/dev/null <<'EOF'
[Journal]
SystemMaxUse=256M
SystemKeepFree=1G
SystemMaxFileSize=16M
SystemMaxFiles=20
EOF

sudo systemctl restart systemd-journald
~~~

Не переносить этот drop-in на другие машины автоматически: политика хранения должна быть согласована для каждого сервера отдельно.

## 4. Проверка

~~~bash
sudo systemctl is-active systemd-journald
sudo systemd-analyze cat-config systemd/journald.conf
sudo journalctl --disk-usage
~~~

В `systemd-analyze cat-config` нужно убедиться, что drop-in `60-limits.conf` присутствует в итоговой конфигурации. `journalctl --disk-usage` показывает фактический объём журналов на момент проверки.

## 5. Ротация и удаление старых журналов

Новые лимиты применяются при дальнейшей работе journald, но не следует считать перезапуск службы командой немедленного удаления всей старой истории.

Если после настройки фактический объём превышает установленный предел, сначала оценить необходимость сохранения старых событий. Принудительная очистка необратима: она удаляет архивные записи, которые могут понадобиться для расследования инцидентов или диагностики.

Только после отдельного решения об очистке можно выполнить:

~~~bash
sudo journalctl --rotate
sudo journalctl --vacuum-size=256M
~~~

Не использовать `--vacuum-size` или другие команды очистки автоматически при каждом применении конфигурации. Не применять `--vacuum-time` или `--vacuum-size` без предварительной проверки того, какие исторические записи будут удалены.

## 6. Область действия и безопасность

- Политика применяется только к назначенному новому VPS, указанному в приватной инвентаризации инфраструктуры.
- На другом VPS настройки journald остаются системными по умолчанию; этот документ не предписывает менять их.
- Домашний сервер не входит в область действия данной настройки.
- В публичном репозитории хранятся только общие параметры и шаблон. Реальные имена узлов, адреса, журналы и диагностические архивы не публикуются.
