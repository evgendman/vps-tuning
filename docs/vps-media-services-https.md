# Публикация медиа-сервисов домашнего Ubuntu-сервера через HTTPS на VPS

**Статус:** документирует проверенную схему по состоянию на 2026-10-17.  
**Назначение:** дополнение к [основному руководству о маршруте VPS → Keenetic через WireGuard](vps-to-keenetic-via-wg-easy.md). Публикуются только отдельные веб-интерфейсы медиа-сервера; вся домашняя LAN не открывается.

## Архитектура

Nginx на VPS принимает HTTPS на отдельном внешнем порту, при необходимости запрашивает дополнительный пароль и передаёт запрос по WireGuard на peer Keenetic 10.8.0.2 и порт приложения. Keenetic перенаправляет соединение на один компьютер под Ubuntu в домашней LAN — на нём размещён медиа-сервер и нужные приложения.

~~~text
Браузер
  │ HTTPS :внешний_порт_VPS
  ▼
Nginx на VPS (TLS и, при необходимости, Basic Auth)
  │ HTTP внутри WireGuard
  ▼
Keenetic: 10.8.0.2:порт_приложения
  │ «Переадресация портов»
  ▼
Ubuntu-медиа-сервер в домашней LAN:порт_приложения
~~~

Внешний HTTPS-порт VPS и порт приложения — разные уровни. Например, клиент открывает Jellyfin на HTTPS-порту VPS 8296, но Nginx обращается к 10.8.0.2:8096. Поэтому на Keenetic настраивается перенаправление 8096/TCP на LAN-IP Ubuntu-медиа-сервера и порт 8096, а не порт 8296.

## Таблица сервисов и портов

| Сервис | HTTPS-порт VPS | Порт Keenetic со стороны WireGuard | Порт приложения на Ubuntu | Дополнительный пароль Nginx |
|---|---:|---:|---:|---|
| Jellyfin | 8296 | 8096/TCP | 8096 | Нет — собственная авторизация Jellyfin |
| Seerr | 8255 | 5055/TCP | 5055 | Да |
| TorrServer | 8292 | 8092/TCP | 8092 | Да |
| Prowlarr | 8696 | 9696/TCP | 9696 | Да |
| Radarr 1080p | 8278 | 7878/TCP | 7878 | Да |
| Sonarr 1080p | 8288 | 8989/TCP | 8989 | Да |
| Radarr 4K | 8279 | 7879/TCP | 7879 | Да |
| Sonarr 4K | 8289 | 8988/TCP | 8988 | Да |

На дату фиксации схемы шесть сервисов были установлены и проверены из браузера: Jellyfin, Seerr, TorrServer, Prowlarr, Radarr 1080p и Sonarr 1080p. Пары 8279 → 7879 и 8289 → 8988 заранее подготовлены в Nginx и SNAT для будущих экземпляров 4K; сами приложения ещё не установлены.

## Правила переадресации на Keenetic

Для каждой пары из таблицы нужно создать или проверить отдельное правило роутера в разделе **«Сетевые правила» → «Переадресация портов»**. В этой схеме все правила направляют трафик на один компьютер под Ubuntu, на котором построен медиа-сервер.

Для правила указываются:
- входящий порт на стороне WireGuard — третий столбец таблицы;
- протокол TCP;
- адрес назначения — постоянный LAN-IP Ubuntu-медиа-сервера;
- порт назначения — порт приложения из четвёртого столбца.

Закрепите LAN-IP компьютера, например DHCP-резервированием. Если адрес компьютера изменится, правила перестанут направлять запросы на нужный сервер.

Примеры:

~~~text
Jellyfin:
10.8.0.2:8096/TCP → <LAN-IP Ubuntu-медиа-сервера>:8096/TCP

Prowlarr:
10.8.0.2:9696/TCP → <LAN-IP Ubuntu-медиа-сервера>:9696/TCP
~~~

Аналогично создаются остальные пары. Внешние HTTPS-порты VPS (8296, 8255, 8292, 8696, 8278, 8288, 8279, 8289) в правилах Keenetic не используются: эти порты принимает Nginx на VPS. На роутере используются именно порты приложений.

Правила должны обслуживать подключения, пришедшие через WireGuard. Не следует без отдельной необходимости публиковать те же сервисные порты на WAN-интерфейсе роутера. Дополнительно должны действовать подходящие разрешающие правила межсетевого экрана Keenetic и обратный путь, описанный в основном WireGuard-руководстве.

## Nginx на VPS

Все восемь виртуальных серверов объединены в один файл:

/etc/nginx/conf.d/router-media-proxies.conf

Nginx подключает файлы conf.d/*.conf и sites-enabled/*. **Резервные копии нельзя хранить ни в одном из этих каталогов**, иначе старые и новые серверные блоки могут одновременно попасть в конфигурацию и создать дубли. Используйте отдельный каталог, например /root/nginx-backups/.

На всех восьми портах используется сертификат Let's Encrypt для домена VPS. Для Seerr, TorrServer, Prowlarr, Radarr и Sonarr включена дополнительная HTTP Basic Authentication через /etc/nginx/.htpasswd. Этот файл, пароли и приватные ключи не должны попадать в репозиторий. Jellyfin исключён из дополнительной Basic Auth, поскольку использует собственную авторизацию.

Приложения могут создавать абсолютные ссылки и перенаправления. Поэтому Nginx передаёт исходный Host вместе с нестандартным портом и сведения о внешнем HTTPS:

~~~nginx
proxy_set_header Host              $http_host;
proxy_set_header X-Forwarded-Host  $http_host;
proxy_set_header X-Forwarded-Port  $server_port;
proxy_set_header X-Forwarded-Proto https;
proxy_redirect http://$http_host/ https://$http_host/;
~~~

Это важно: без порта в Host/Forwarded-заголовках приложение может перенаправить браузер на стандартный HTTPS-порт 443; без корректной схемы — сформировать ссылку http://. Исправление проверено на Prowlarr: после авторизации редирект сохраняет HTTPS и внешний порт 8696. Prowlarr, Radarr 1080p, Sonarr 1080p, Seerr и TorrServer проверены из браузера.

Перед применением изменений проверяйте конфигурацию командой:

~~~bash
sudo nginx -t
~~~

Только при успешной проверке выполняйте:

~~~bash
sudo systemctl reload nginx
~~~

## Дополнительная SNAT-служба без изменения wg-easy

Интерфейс WireGuard wg0 находится внутри сетевого пространства Docker-контейнера wg-easy, а не непосредственно на хосте VPS. Хост отправлял пакеты к 10.8.0.2 через Docker bridge с исходным адресом 172.17.0.1. Прямой запрос с таким источником завершался тайм-аутом, хотя запрос изнутри контейнера работал. После подмены источника на WireGuard-адрес VPS 10.8.0.1 обратный обмен заработал.

Для этого на VPS установлена отдельная служба systemd:

- скрипт: /usr/local/sbin/wg-easy-extra-snat;
- unit: /etc/systemd/system/wg-easy-extra-snat.service;
- служба включена в автозапуск и на момент проверки активна;
- список TCP-портов: 8096, 5055, 8092, 9696, 7878, 8989, 7879, 8988.

Служба **не редактирует** /root/.wg-easy, wg0.conf, WG_POST_UP, WG_POST_DOWN, ключи или список WireGuard peers. Она не меняет постоянные параметры wg-easy и не требует перезапуска контейнера для применения SNAT. Внешний скрипт вызывает docker exec и управляет только дополнительными рабочими правилами iptables в сетевом пространстве контейнера.

Правила ограничены конкретным источником и назначением:
- источник 172.17.0.1/32;
- назначение 10.8.0.2/32;
- выходной интерфейс wg0;
- протокол TCP и конкретный порт назначения из таблицы;
- новый адрес источника 10.8.0.1.

Скрипт проверяет правила при запуске и примерно каждые пять секунд. Поэтому после пересоздания контейнера он повторно добавляет недостающие правила, как только контейнер и wg0 становятся доступны. Правила для 4K-портов подготовлены заранее, независимо от наличия приложений.

Команды контроля:

~~~bash
systemctl is-enabled wg-easy-extra-snat.service
systemctl is-active wg-easy-extra-snat.service
systemctl status wg-easy-extra-snat.service --no-pager
sudo /usr/local/sbin/wg-easy-extra-snat check
docker exec wg-easy iptables -t nat -S POSTROUTING
~~~

Ожидаемое состояние службы — enabled и active; в цепочке POSTROUTING должны присутствовать восемь дополнительных SNAT-правил и штатное MASQUERADE для клиентов WireGuard. Штатное правило MASQUERADE удалять или изменять нельзя.

### Откат

Полное отключение службы и удаление управляемых ею дополнительных SNAT-правил:

~~~bash
sudo systemctl disable --now wg-easy-extra-snat.service
~~~

Это не меняет конфигурацию wg-easy, но удаляет и SNAT-правило Jellyfin: внешний прокси Jellyfin перестанет работать, пока службу не включить снова:

~~~bash
sudo systemctl enable --now wg-easy-extra-snat.service
~~~

Обычная команда systemctl stop также останавливает службу и удаляет её дополнительные правила, но не отключает автозапуск. Не редактируйте WG_POST_UP и WG_POST_DOWN ради этой схемы.

## Проверка всей цепочки

1. На VPS: ip -4 route get 10.8.0.2 — маршрут должен идти через Docker-контейнер wg-easy.
2. В контейнере: docker exec wg-easy wg show — проверить актуальный handshake peer Keenetic.
3. На VPS: sudo /usr/local/sbin/wg-easy-extra-snat check — все восемь SNAT-правил должны присутствовать.
4. Проверить прямой HTTP-доступ с VPS к http://10.8.0.2:<порт>/.
5. Проверить Nginx без пароля: семь защищённых портов должны возвращать 401 Unauthorized; Jellyfin должен отвечать собственной авторизацией.
6. Проверить доступ из внешнего браузера, успешный вход и сохранение HTTPS и нестандартного порта в перенаправлениях.

На дату проверки шесть установленных сервисов проходили всю цепочку VPS → WireGuard → Keenetic → Ubuntu-медиа-сервер → приложение. Два 4K-порта подготовлены на VPS, но после установки приложений требуется проверить их прослушивание и соответствующую переадресацию на Keenetic.
